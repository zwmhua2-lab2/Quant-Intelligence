# 1. Problem

`QI-P1-03-I01` persisted the P1 design candidate correctly in every respect except one:
the `Dependency` fields of `P1_IMPLEMENTATION_PLAN.md` batches **P1-I02 / P1-I03 / P1-I04**
contained an inter-batch dependency assertion that **does not exist in the Authoritative
Design Input**.

The same file's §1 (`P1-P-02`) already stated the correct position:

```text
The Design Input states the batch sequence (§24 order)
but does not separately declare a formal inter-batch dependency contract.
```

So the document was **internally inconsistent**: §1 correctly denied a formal dependency
contract, while §2–§5 asserted one. This is a persistence-fidelity defect, not a
requirement or architecture defect.

**Correct position for a persistence Executor:** the Design Input declares batch
sequence, scope and acceptance boundaries — it does **not** declare that a later batch
formally depends on an earlier batch's outcomes or acceptance. A persistence layer must
not infer such a relationship.
